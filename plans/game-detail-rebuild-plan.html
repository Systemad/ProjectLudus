Game detail rebuild plan

A ground-up Android-native redesign based on the CS2 reference layout, the uploaded scroll recording, and the current Ludus data model.

Planning only — production code unchanged

Why this is a rebuild

The current page combines a React Native scroll container with many independently measured Compose hosts. The plan replaces that architecture with one vertical Compose tree, using React Native bridges only for image and chart libraries that require them.

Implementation sequence

  1. Define the screen modelMove queries, derived section data, tab state, summary state, chart range, authentication branching, and action handlers into one screen hook.
  2. Create one Android composition treeUse one safe-area boundary, one Host, one vertical scroll container, and explicit section boundaries.
  3. Build the header and tabsHide the stack header, render one 57dp top bar, and keep Overview, Media, and Links local to the detail screen.
  4. Build media as one unitKeep hero, scrim, chips, overlapping cover, title, and metadata in one measured layout boundary.
  5. Build the four actionsUse four equal weighted surfaces. Signed-out actions route to profile instead of replacing the row.
  6. Build the summary cardPut padding on the inner content column and center Read more inside the full-width card.
  7. Build the shared metadata gridUse configurable columns, real cell padding, correctly sized dividers, and one controlled page inset.
  8. Attach Steam, chart, and related dataKeep chart range state local to the chart section and related games as a horizontal pill rail.
  9. Remove competing implementationsDelete duplicate detail shells, duplicate Steam presentation code, and section-specific spacing hacks.
  10. Verify on deviceCheck top, middle, and bottom scroll positions, interactions, safe areas, chart dismissal, and normal Metro reload behavior.

Component boundaries

use-game-detail-screen.tsLogic, queries, state, actions, and view-model shaping.
game-detail-screen.android.tsxOne native scroll tree and section composition.
metadata-grid.android.tsxOne configurable grid for Steam, ratings, and game facts.

Non-negotiable rules

One vertical scroll tree
One shared content inset
One authoritative Android detail implementation
Material defaults for Compose colors and shapes
No raw colors in new Compose UI
No generated-file or OpenAPI edits
No Metro cache clear for every source edit
