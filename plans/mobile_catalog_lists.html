Mobile Catalog Lists

Replace the removed category browser with a data-first Lists screen. The mobile app reuses existing Catalog API endpoints and generated TanStack Query hooks; no new backend service or API layer is needed.

Architecture

Catalog database
      │
      ├── Catalog API: IGDB popscore and Steam chart endpoints
      │
      └── Kubb-generated hooks
              │
              ▼
      Mobile Expo Router
      └── /(browse)/index
          └── Catalog Lists screen
              ├── Trending rail
              ├── Most Played rail
              └── Hot Releases rail

Catalog owns the data and query rules. The mobile feature only composes the results into a screen. Game cards and carousels remain shared entities, so Discover and Lists use the same navigation and visual rules.

Lists in the first version

  • Trending: IGDB popscore with popularity type 9.
  • Most played: Steam chart type most-played.
  • Hot releases: Steam chart type hot-releases.

The web app also has popular-releases. It can be added later as another rail without changing the architecture.

Existing API calls

useIgdbGetPopscore({
  query: { PopularityTypeId: "9", Page: 1, PageSize: 12 },
});

useSteamChart({
  query: { Type: "most-played", Page: 1, PageSize: 12 },
});

useSteamChart({
  query: { Type: "hot-releases", Page: 1, PageSize: 12 },
});

Mobile feature structure

src/
├── app/(browse)/index.tsx
└── features/catalog-lists/
    ├── index.ts
    ├── catalog-lists-screen.tsx
    └── catalog-list-rail.tsx
  • catalog-lists-screen.tsx owns the three generated queries.
  • catalog-list-rail.tsx renders each title, state, and carousel.
  • GameCarousel and GameCard remain shared UI primitives.
  • Each card navigates to the existing Browse game-detail route.

Screen behavior

  • One vertical scroll view contains the three sections.
  • Each section has a horizontal, freeform carousel with approximately three visible cards.
  • Loading, empty, and retry states are handled independently per section.
  • TanStack Query owns request caching; Expo Router keeps the Browse stack mounted.
  • No category grid, filter sheet, category slugs, or hardcoded category metadata.

Implementation order

  1. Create the catalog-lists feature slice.
  2. Replace the temporary Browse placeholder with the Lists screen.
  3. Wire the three existing generated hooks.
  4. Reuse the shared game carousel and detail navigation.
  5. Run pnpm run fmt, TypeScript checks, and lint.

Out of scope

  • No Catalog API changes.
  • No new DTOs or mobile-specific endpoints.
  • No new query client or manual query-key construction.
  • No implementation of popular-releases in the first pass.
